## Architectural Rules

- **2026-08-22** — **The upload to object storage happens BEFORE the transaction; only the row write is inside it.** engineering-standards §13 forbids synchronous outbound HTTP inside a request holding a transaction open, and holding row locks for the length of a 3G upload lets one slow phone block the table. Consequence accepted in writing: a stored object whose transaction then fails is an orphan in the bucket. That is the correct trade — the alternative loses the player's upload to protect a few kilobytes, and the path is content-addressed, so a retry reuses the same key rather than adding a copy.
- **2026-08-22** — **`moderation_status` on the media 201 is ALWAYS `pending`, never `cleared`.** Moderation & Safety consumes `player.media_uploaded` asynchronously through the outbox (Law 6), so no verdict exists when the response is written and claiming one would be this engine asserting another engine's truth. Written into the contract: a client must not read `pending` as `blocked` (the owner sees their own upload immediately), and a PUBLIC surface must read the verdict fresh rather than trust this snapshot.
- **2026-08-22** — **Player media paths are CONTENT-ADDRESSED and derived in ONE place**: `player-media/{kind}/{playerId}/{sha256}.{ext}`, shared by both drivers through `MediaPath`, so a photo keeps the same key whichever driver stored it. Deriving it separately per driver would orphan every object when an environment moves from local to R2. The extension comes from the SERVER's `finfo` sniff first and the client filename only as fallback — trusting the client string is how a `.php` lands in a public bucket.
- **2026-08-22** — **`R2PlayerMediaDriver` builds the public URL itself, and the factory REFUSES to construct the driver while `R2_PUBLIC_URL` is empty.** R2's S3 endpoint is private and is not the address a browser fetches from (that is the bucket's r2.dev domain or a custom domain), so letting the adapter derive a URL would ship links that resolve for nobody and a card showing a broken image that looks like an upload bug rather than a missing setting. The guard's message names the fix; verified it fires.
- **2026-08-22** — **The `player-media-upload` limiter is keyed by USER, not IP**, unlike the public read throttles. A whole club on one wifi, or a row of players at an internet cafe, share an address; an IP key would let one player's retries lock out everyone beside them.
- **2026-08-22** — **The card stat strip fills one line, or whole lines, never a line and a half.** `stripColumns(count)` gives up to three items a column each; four or more go to two columns. An orphaned last item reads as something that failed to load, on an object built to be screenshotted.
- **2026-08-22** — **Player media uploads go through the API, never browser-direct to R2.** A browser holding a bucket credential skips the MIME allow-list, the size ceiling, the per-player throttle, the audit entry (Law 5) and the `player.media_uploaded` event Moderation & Safety consumes (Law 10). Player photos are public content; the gate is the point.
- **2026-08-21** — **A stat label sits at NORMAL tracking, never eyebrow tracking.** The system's 0.14em uppercase is right for a section label and wrong under a number: letterspacing pulls the label wider than the figure above it and the pair stops reading as one unit.
- **2026-08-21** — **`min-h-0` on a scrolling grid column is load-bearing.** A grid item's automatic minimum size is its content, so without it the column refuses to shrink and scrolls the PAGE instead of itself.
- **2026-08-21** — **`.kx-scroll-none` only goes on a pane whose scrollability is already evident from clipped content.** Hiding a scrollbar anywhere else removes the only affordance saying there is more; the warning is written into the utility in `globals.css`.
- **2026-08-21** — **A config list that supplies a fixed set falls back WHOLE, never partially topped up.** `player.card.featured_stats` edited down to two keys falls back to all three defaults rather than filling the gap, so a mis-edit surfaces instead of being quietly patched.
- **2026-08-21** — **A decorative layer that changes luminance is PART OF THE GROUND, and the ground is what has to clear AA.** Recorded in ADR-0014. A contrast test that measures a layer the user never sees in isolation is not measuring anything: the card's token test was green for an hour while the shipped surface sat at 4.19:1, because it measured the bare gradient and the bare gradient was never what a reader saw.
- **2026-08-21** — **CSS composites blend modes in GAMMA-ENCODED sRGB, not linear light.** Doing the arithmetic in linear light overstates the remaining contrast headroom, so `design-tokens.test.ts` encodes, blends, then decodes before measuring. The first mock render in this packet had it wrong and was corrected.
- **2026-08-21** — **A white-on-transparent asset must be composited onto a DARK ground before it can be judged.** A near-blank white preview of one is not evidence the file is empty; it is the preview background showing through. Hit twice in one session (the generated portrait placeholder, then the supplied artwork), so check the alpha channel before concluding an asset failed to generate.
- **2026-08-21** — **Quantisation level for a supplied pattern is a function of the artwork's SPATIAL FREQUENCY, not a fixed setting.** Flat sparse art palettises to 8 alpha levels invisibly; fine regular hatching moires and bands at the same setting and needs more (the zigzag ships 12), and the downscale runs a box filter so fine lines are prefiltered rather than point-sampled. Judge each asset, do not reuse the last one's numbers.
- **2026-08-21** — **A card pattern is a SHAPE, not a colour.** Seamless tiles ship as SVG data URIs used as `mask-image` and take their colour from `currentColor`, the same technique `<Wordmark>` already uses: a `var()` inside a data URI does not resolve, and a baked fill would be a colour literal (a refusal trigger).
- **2026-08-21** — **The card portrait is an absolutely positioned masked LAYER, never a column.** Content layout is identical with and without it, so a card with no portrait is not a card with a hole in it.
- **2026-08-21** — **A card dresses from the `--card-*` tokens, never from `--primary`/`--accent`.** A card lands in a WhatsApp thread as an image, so its colours must not depend on the sender's theme: the `--card-*` stops are declared once in `:root` and are never re-declared in the light block (same rule as `--pitch-*`, ADR-0011).
- **2026-08-21** — **ADR-0012's sub-AA white-on-brand deviation does not travel.** It was accepted for a one-word button label; any surface carrying small text (11–14px), a full name, or a stat row must clear 4.5:1 on its own tokens.
- **2026-08-21** — **A white glow is capped at 12% and anchored where only large display text sits.** On the card it lives at the top of the panel, over the wordmark and shirt number only, because a white glow lifts whatever it crosses and only large display text can afford it.
- **2026-08-19** — **DESIGN_LANGUAGE §2.1's neutral hue-lock locks HUE, not chroma.** A neutral that reads cool/slate is fixed by lowering chroma at hue 264 (measure it as the R-B channel spread); a neutral that needs more separation from its neighbour is fixed by raising L. Never reach for chroma to buy depth.

## Craftsmanship Standards

- **2026-05-20** — **File size hard limits**: no source file > 400 LOC, no function/method > 50 LOC, no class > 250 LOC. Violation is a refusal trigger for Implementer. Reason: maintainability, testability, code review.
- **2026-05-20** — **Naming discipline**: verbs for functions (`calculateStake()`), nouns for variables/classes; no abbreviations except project-canonical (RP, WP, ADR, OTP, TTL, DAU, KPI); booleans start with `is`/`has`/`can`/`should`; internal keys are `snake_case` strings (`result_confirmed`), display strings are configurable labels; no Hungarian notation or `I` prefix on TS interfaces.
- **2026-05-20** — **Backend reusability**: domain logic in `app/Modules/<Engine>/Domain/` is framework-agnostic (no Eloquent, no HTTP); Application services (one public method per use case) orchestrate domain + persistence + events; Repositories own all Eloquent queries; HTTP controllers ≤ 30 lines (validate → call service → return resource); cross-module reusable code lives in `app/Support/`; DRY at domain level, WET at boundaries.
- **2026-05-20** — **Frontend reusability**: components in `src/components/ui/` (pure, presentational); `src/components/<feature>/` (feature-bound containers); `src/components/site/` (shell pieces); hooks own data-fetching + state shape; API client in `src/lib/api/` (generated from OpenAPI); no business calculations in UI; server components by default.

- **2026-05-20** — **Database indexing discipline**: index every foreign key (mandatory); index every column in WHERE/ORDER BY/JOIN on hot paths; composite indexes put most-selective column first, equality before range; partial indexes for mostly-null columns or filtered queries (e.g. `WHERE archived_at IS NULL`); time-series tables (analytics, audit logs) partitioned monthly; EXPLAIN required on hot-path reads before merge; unused indexes dropped after 30 days in production.

## Glossary

- **Sankofa** — The project's continuous documentation subagent; named after the Akan symbol meaning "go back and fetch it." Owns and maintains `docs/JOURNAL.md`.
- **CodeGenerator seam** — Pattern for testing code that depends on a final PHP class. Implemented via interface (e.g., `CodeGenerator`) with production binding (e.g., `RandomCodeGenerator` wrapping `Random\Randomizer`) and test binding (e.g., `StaticCodeGenerator`). Applicable across Kalaanba whenever wrapping `final` classes from PHP/Laravel.
- **Respect Points (RP)** — The non-monetary currency of the Challenge system; transferred between clubs based on call-out outcomes (win, draw, forfeit, ducked).
- **Fan Buzz** — A normalized hype score for a Challenge, mixing reactions, WhatsApp shares, predictions, comments, and view velocity. Displayed as a percentile against rolling-average buzz, not an absolute number.
- **Scene pack** — The hand-curated library of Challenge card background art plates (gauntlet, lightning, war-drums, etc.) the card composer draws from.
- **`--card-*` (theme-stable tokens)** — The seven card fills (`--card-flare`/`-deep`, `--card-dusk`/`-deep`, `--card-deep`/`-deep`, `--on-card`) declared once in `:root` and never re-declared for light, so a card screenshotted into a chat looks the same whoever sent it. Same species as `--pitch-*` (ADR-0011); introduced by ADR-0014.
- **`<LiveSurface>`** — Opt-in component for aurora/mesh/glass visual effects; premium visual treatment not used by default primitives.
- **Theme switcher v3** — Cookie-based SSR-stable user theme choice + settings-only segmented control UI (future implementation post-Phase 1).
- **Work Packet (WP)** — Atomic unit of work that flows through all 10 Agent OS pipeline stages. Identified by `WP-YYYYMMDD-<slug>`. Every PR carries the WP ID and must show all 10 stage boxes ticked before merge. Example: `WP-20260520-configurable-draw-cost`. Within a larger phase (e.g., Phase 0.6), packets may be lettered sequentially: WP-A (identity foundation), WP-B (OTP + policies), WP-C (admin audit), etc.
- **Agent OS** — The governance meta-layer (10-stage pipeline, Constitution, chat modes, contracts, ADR cadence) that sits on top of Build Plan and describes _how_ every change is built (intake → release packet), orthogonal to _what & when_ (Build Plan's phasing).
- **AdminAuditEntry** — Readonly value object capturing actor_id, actor_role, request_id, route, method, path, response_status, payload_redacted (KEYS only, PII VALUES redacted), occurred_at. The canonical shape of an append-only audit log row; written only by `AdminAuditMiddleware`.
- **ApiError** — Frontend exception class wrapping the backend's standard error envelope (`{error: {code, message, details?, request_id?}}`). Stable `code` field (e.g. `auth.super_admin_only`) drives UI behavior; `message` is for display only. Falls back to `api.unknown_error` for non-conforming responses.
- **kx:next:** — Redis key prefix for Next.js Incremental Static Regeneration (ISR) cache entries. Used by cache-handler in production to namespace ISR state separately from other app caches.
- **themeBootstrapScript** — IIFE injected into `<head>` to set `data-theme` before hydration (FOUC fix). Reads localStorage (`kalaanba-theme` key) + `matchMedia("(prefers-color-scheme: light)")` before React hydration begins.
- **data-theme attribute** — Canonical theme switch on `<html>` element: `data-theme="dark"` (default, `:root` with `color-scheme: dark`) or `data-theme="light"` (`:root[data-theme="light"]`). Semantic alternative to class-based toggling.
- **`--kx-*` compat aliases** — Legacy CSS token aliases (e.g., `--kx-bg: var(--bg)`) kept only for archived components under `src/components/_archive/`; dropped once that folder is fully deleted.
- **UUIDv7-ordered** — Our shorthand for the values produced by Laravel's `HasUuids` trait via `Str::orderedUuid()`. Technically RFC 4122 v4 with millisecond-ordered prefix (not strictly UUIDv7 spec), but operationally equivalent: k-sortable, index-friendly, monotonic ordering for efficient database scans. Used throughout Kalaanba as the canonical PK type for new tables post-users.id migration (ADR-0003). Documented in ADR-0003.

## Glossary

- **Cozy yet authoritative** — motion design principle for Kalaanba UI: soft welcoming arrival (ease-entrance with overshoot), confident firm settle (ease-exit snappy). Animates comfort + confidence simultaneously.
- **Pressable** — primitive component providing single source of truth for interaction recipe (44px min hit area, ease-out motion, hover lift, active press, focus-visible ring). All other UI primitives compose Pressable.
- **Overlay** — primitive component providing single source of truth for backdrop concerns (z-index, scroll-lock, focus-trap, overscroll-contain, click-outside, ESC handler). All modal-like surfaces (Dialog, BottomSheet, Drawer, ActionSheet, Popover) compose Overlay.
- **BottomSheet** — mobile-primary modal component. At viewport ≥768px morphs to centered Dialog with same API, different chrome. Reason: unified state machine, responsive geometry.
- **KeyboardFooter** — sticky action bar positioned above keyboard on mobile, below content on desktop. Persists across route transitions.
- **LiveSurface** — opt-in wrapper component for aurora/mesh/glass visual effects; premium treatment not used by default primitives. Respects `prefers-reduced-motion`.
- **Tier 12** — engine-specific deferred components (MatchCard, StandingsTable, EventLogger, LineupPitch, ZonePicker, etc.) listed in Component Inventory for forward-compat awareness. MUST NOT be built until that engine enters its build window per Build_Plan.md.
- **Mobile chrome** — Phase 2.5 mobile-specific UI layer: `Overlay`, `BottomSheet` (morphs to `Dialog` on desktop ≥768px), `BottomNav`, `KeyboardFooter`, `Toast` (bottom-center mobile, top-right desktop). Includes viewport meta, theme-color, min-h-dvh shell.
- **Motion tokens** — CSS custom properties for animation: three easings (`--ease-out` soft default, `--ease-entrance` with overshoot, `--ease-exit` snappy); three durations (`--dur-quick 160ms`, `--dur-graceful 280ms`, `--dur-deliberate 420ms`). Mobile shaves graceful/deliberate ~15%.
- **44px hit area** — WCAG 2.1 minimum touch target size for mobile. Enforced refusal trigger; QA Stage 8 refuses sign-off if violated. Kalaanba Button sm bumped h-9 → h-11 to comply.
- **iOS zoom trap** — browser auto-zoom on input focus when font < 16px. Solution: `--font-input: max(16px, 1rem)` token; TextField API requires `inputMode`, `autoComplete`, `enterKeyHint`.
- **Design system mandatory** — `.github/instructions/design-system-mandatory.instructions.md` instruction file (applyTo `kalaanba-front/**`) forcing all agents to read DESIGN_LANGUAGE.md before UI work and cite specific sections. Parallels `engine-docs-mandatory.instructions.md` for discipline enforcement.
- **`pressableBase`** — Class-string export from `pressable.tsx`. Canonical interaction recipe consumed via `cn()` by every clickable. Expresses press via state change + `--shadow-pressed` inset, never via translate/scale.
- **`--shadow-pressed`** — Inset-shadow token (dark/light variants) expressing press without geometric motion. Replaces deprecated translate/scale approach for accessible, motion-respecting press feedback.
- **`theme-flipping`** — Transient class added to `<html>` for 200ms during theme change to enable smooth color/border/shadow cross-fade. Gated by `@media (prefers-reduced-motion: no-preference)`.
